# .NET 10.0.302 baseline adoption

Date: 2026-07-31

## Reviewed baseline

- .NET SDK: `10.0.302`
- .NET runtime container images: `10.0.10`
- `global.json` roll-forward policy: `latestPatch`
- Prerelease SDK selection: disabled

The SDK and runtime versions are intentionally separate. The SDK feature-band
version is not a valid substitute for the runtime servicing tag.

## Repository adoption

The following product repositories pin and resolve SDK `10.0.302`:

- `CanDoItAll`
- `CanDoItAll.AgentFramework`
- `CanDoItAll.AgentFramework.Rag`
- `CanDoItAll.AgentFramework.SemanticCompletion`
- `CanDoItAll.CodeAnalysis`
- `CanDoItAll.Components`
- `CanDoItAll.Economy`
- `CanDoItAll.FileTools`
- `CanDoItAll.IPFS`
- `CanDoItAll.Ledger`
- `CanDoItAll.Mcp`

CI definitions use each repository's `global.json` rather than duplicating a
floating SDK version. NuGet build adapters run `dotnet` from the owning
repository root so SDK selection cannot be inherited from the caller's working
directory.

## Docker validation

- `CanDoItAll.IPFS` passed Docker convention checks, Dockerfile build checks,
  image builds, disposable service startup and health checks, and teardown.
- `CanDoItAll.Ledger` resolved its Compose model and built the `economy-node`,
  `demo-seeder`, and `accountapp` images.
- Its three additional .NET Dockerfiles also build successfully. Two obsolete
  copies of a nonexistent `docker/components/Directory.Build.props` were
  removed, and the standalone seeder was serialized with `/m:1` to prevent its
  existing MSBuild output race.
- All active .NET Docker build stages use SDK `10.0.302`. ASP.NET Core and .NET
  runtime stages use servicing release `10.0.10`.
- The shared Ledger Compose convention audit still reports three existing
  committed-development-secret errors and eight warnings covering host-wide
  port bindings, Docker ignore coverage, a database bind mount, and the nginx
  image's root user. These are independent of SDK and image build correctness.

## Repository validation findings

- `CanDoItAll` builds in Release with no warnings or errors. Its CI-filtered
  solution test command exceeded the 30-minute local validation window.
- `CanDoItAll.FileTools` passed 463 tests.
- `CanDoItAll.Ledger` builds in Release; 568 of 576 tests pass. The eight
  existing bUnit failures require `TooltipService` registration.
- `CanDoItAll.AgentFramework` still references the former in-repository
  `CanDoItAll.Components.BaseLib` path and cannot build until that dependency is
  migrated to the released cross-repository package contract.
- `CanDoItAll.Economy` restore is blocked by existing direct dependency
  downgrades from runtime package `10.0.10` to `10.0.8` and `10.0.7`.
- `CanDoItAll.Mcp` restore is blocked by the unavailable
  `CanDoItAll.Components.Sandbox` package. Its repository validator also retains
  an obsolete licensing assertion.

These findings are not SDK-selection failures and were not hidden by fallback
logic. They require separate dependency or test maintenance.

## Deployment note

Existing self-contained application deployments embed their previous runtime.
They must be republished and redeployed to receive the .NET `10.0.10` runtime
servicing fixes. That deployment work is separate from this source and package
baseline adoption.
