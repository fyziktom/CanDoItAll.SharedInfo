## Findings

- All source repositories had a `.gitignore`, but only two shared an identical file and
  many entries were product- or bundle-specific.
- Only `CanDoItAll.CodeAnalysis` had a root `.editorconfig`.
- Nine repositories had `global.json`: eight pinned `10.0.200`; one pinned `10.0.301`.
- `Directory.Build.props` consistently enabled nullable references and implicit usings,
  but mixed shared defaults with product/package metadata.
- README coverage varied from minimal project maps to detailed setup and packaging guides.
- Tooling was mostly flat or split inconsistently between `tools` and `scripts`.
- Existing NuGet scripts used incompatible names and parameter shapes.
- The main repo `codex` folder mixed reusable skills with thousands of product bundles and
  proof files, confirming the need for a separate shared home.
- The existing Components plugin used a stale path into the main repository even though
  the MCP project now lives in `CanDoItAll.Mcp`.

## Included In Initial Consolidation

- Canonical standards and repository templates.
- Repository catalog, clone helper, inventory helper, SharedInfo validator, and NuGet
  orchestrator/template.
- Main-repo reusable skills, support resources, architecture guides, and generic agent
  profiles.
- Reusable CFO skills.
- Repaired Components MCP plugin packaging.

## Deliberately Deferred

- Changes to any source repository.
- Product-specific tools and build logic.
- Active/closed bundles, proof, logs, screenshots, and generated output.
- Web-app/agent product templates from the main repository.
- Economy simulator and Cognitive Memory governance skills, which are product-specific.
- AgentFramework's `repository-playbook`, which hard-codes that repository's workflow.
- The RAG Qdrant skill tree. Its current packages contain non-standard frontmatter and
  nested discoverable skills; normalize and license-review it before shared adoption.
